LVS架构

LVS (Linux Virtual Server) 是 Linux 内核级别的负载均衡解决方案，由中国的章文嵩博士在 1998 年创建，是目前性能最高的负载均衡软件之一。

​
 1# 核心组件
 2Director Server (DS)    # 调度器/负载均衡器
 3Real Server (RS)        # 真实服务器/后端服务器
 4VIP (Virtual IP)        # 虚拟IP（对外提供服务的IP）
 5DIP (Director IP)       # 调度器IP（Director的内网IP）
 6RIP (Real Server IP)    # 真实服务器IP
 7
 8# 连接术语
 9CIP (Client IP)         # 客户端IP
10IPVS                    # IP Virtual Server（内核模块）
11ipvsadm                 # LVS管理工具

1. LVS（Linux Virtual Server）

定义： 项目名称 / 整体解决方案

本质：

  • 目标：在Linux平台实现高性能、高可用的服务器集群
  • 包含：内核模块（IPVS）+ 用户态工具（ipvsadm）+ 高可用方案（Keepalived）

定义： Linux内核模块 / 负载均衡引擎

  • 工作在Linux内核的Netfilter框架中

01 LVS工作模式

LVS（Linux Virtual Server）是Linux内核级别的负载均衡解决方案，有三种主要工作模式：

1. NAT模式（Network Address Translation）

工作原理：

  • Director Server（调度器）接收客户端请求
  • 修改请求包的目标IP为Real Server IP
  • Real Server处理后，响应包发回Director
  • Director修改源IP为VIP，返回给客户端

特点：

  • Real Server可使用任何操作系统
  • Real Server只需配置Director为网关
  • 节省公网IP（只需Director有公网IP）
  • Director成为性能瓶颈（请求和响应都经过）
  • 支持端口映射

适用场景：
小规模集群（10-20台），Real Server在私网

2. DR模式（Direct Routing，直接路由）

工作原理：

  • Director接收请求，修改MAC地址为Real Server MAC
  • Real Server处理后，直接返回给客户端（不经过Director）
  • Real Server配置VIP在lo接口（抑制ARP）

特点：

  • 性能最高（响应不经过Director）
  • Director不是瓶颈
  • 支持大规模集群
  • Real Server必须与Director在同一网段
  • 不支持端口映射
  • Real Server需要抑制ARP响应

适用场景：
大规模高性能集群，最常用模式

关键配置：

1# Real Server需要配置（抑制ARP）
2echo 1 > /proc/sys/net/ipv4/conf/lo/arp_ignore
3echo 2 > /proc/sys/net/ipv4/conf/lo/arp_announce
4echo 1 > /proc/sys/net/ipv4/conf/all/arp_ignore
5echo 2 > /proc/sys/net/ipv4/conf/all/arp_announce
6
7# lo接口配置VIP
8ifconfig lo:0 VIP netmask 255.255.255.255

3. TUN模式（IP Tunneling，IP隧道）

工作原理：

  • Director将请求包封装在新的IP包中（IP隧道）
  • Real Server解封装后处理请求
  • Real Server直接返回响应给客户端

特点：

  • Real Server可跨地域部署（不受网段限制）
  • 响应不经过Director
  • 适合跨机房负载均衡
  • Real Server需要支持IP隧道
  • 不支持端口映射
  • 配置复杂

适用场景：
跨地域、跨机房的大规模集群

四种调度算法

LVS支持10种调度算法，常用的有：

静态算法：

  • RR（Round Robin）：轮询，平均分配
  • WRR（Weighted RR）：加权轮询，按权重分配
  • DH（Destination Hashing）：目标地址哈希
  • SH（Source Hashing）：源地址哈希

动态算法：

  • LC（Least Connections）：最少连接，分配给连接数最少的服务器
  • WLC（Weighted LC）：加权最少连接（默认算法）
  • SED（Shortest Expected Delay）：最短期望延迟
  • NQ（Never Queue）：永不排队
  • LBLC：基于本地的最少连接
  • LBLCR：基于本地的带复制功能的最少连接

三种模式对比

特性 NAT模式 DR模式 TUN模式
性能 较低 最高 高
网络要求 私网 同网段 可跨网段
端口映射 支持 不支持 不支持
Real Server配置 简单 中等（需抑制ARP） 复杂（需支持隧道）
Director负载 高（双向流量） 低（仅入站） 低（仅入站）
Real Server OS 任意 任意 需支持IP隧道
公网IP需求 仅Director 仅Director 仅Director
适用场景 小规模 大规模高性能 跨地域部署

02 DR模式实验

DR 模式的关键是：

  • Director 和 Real Server 必须处于同一个二层广播域；
  • VIP 同时配置在 Director 和 Real Server 上；
  • Real Server 必须避免对 VIP 的 ARP 请求进行响应；
  • Director 只修改目标 MAC，不修改 IP 和端口；
  • Real Server 的响应绕过 Director，直接返回客户端。

1、安装软件

在 Director 上：

1apt update
2apt install -y ipvsadm nginx

在 Real Server 上：

1apt update
2apt install -y nginx

2、配置 Real Server

以下步骤需要在 RS1 和 RS2 上分别执行。

启动 Web 服务

1systemctl enable --now nginx

检查服务状态：

1systemctl status nginx
2ss -lntp | grep ':80'

设置不同的页面内容

Debian/Ubuntu 默认首页：/var/www/html/index.nginx-debian.html 或/var/www/html/index.html

在 RS1 上：

1# cat > /usr/share/nginx/html/index.html <<'EOF'
2cat > /var/www/html/index.nginx-debian.html <<'EOF'
3<h1>Response from RS1 - 192.168.10.11</h1>
4EOF

在 RS2 上：

1# cat > /usr/share/nginx/html/index.html <<'EOF'
2cat > /var/www/html/index.nginx-debian.html <<'EOF'
3<h1>Response from RS2 - 192.168.10.12</h1>
4EOF

先直接访问 Real Server，确认 Web 服务正常：

1curl http://192.168.10.11
2curl http://192.168.10.12

在 lo 接口配置 VIP

在 RS1、RS2 上分别执行：

1ip addr add 192.168.10.200/32 dev lo

检查：

1ip addr show dev lo

预期可以看到：

1inet 192.168.10.200/32 scope global lo

为什么配置到 lo 接口？

DR 模式中，Real Server 需要接收目标IP为 VIP 的数据包。因此，Real Server 必须认为 VIP 是本机地址。

将 VIP 配置在回环接口上，可以让 Real Server接收目标IP为 VIP 的报文，同时避免把 VIP作为正常接口地址直接暴露在二层网络中。

配置 ARP 抑制

这是 DR 模式最关键的配置之一。

在 RS1、RS2 上执行：

 1cat >> /etc/sysctl.d/99-lvs-dr.conf <<'EOF'
 2net.ipv4.conf.all.arp_ignore = 1
 3net.ipv4.conf.default.arp_ignore = 1
 4net.ipv4.conf.lo.arp_ignore = 1
 5
 6net.ipv4.conf.all.arp_announce = 2
 7net.ipv4.conf.default.arp_announce = 2
 8net.ipv4.conf.lo.arp_announce = 2
 9EOF
10
11sysctl --system

检查配置：

1sysctl net.ipv4.conf.all.arp_ignore
2sysctl net.ipv4.conf.all.arp_announce
3sysctl net.ipv4.conf.lo.arp_ignore
4sysctl net.ipv4.conf.lo.arp_announce

参数含义

arp_ignore = 1

只在目标IP配置于接收ARP请求的接口上时响应ARP。

这样，Real Server 不会通过物理网卡抢答 VIP 的ARP请求。

arp_announce = 2

发送ARP请求时，尽量使用最合适的接口地址作为源IP，减少多网卡环境下的ARP混乱。

3、配置 LVS Director

以下命令只在 Director 上执行。

加载 IPVS 模块

1modprobe ip_vs
2modprobe ip_vs_rr

检查：

1lsmod | grep ip_vs

给 Director 配置 VIP

1ip addr add 192.168.10.200/32 dev eth0

开启 IP 转发说明

LVS-DR 模式不依赖三层 IP 转发，通常不需要开启 net.ipv4.ip_forward。

可以保持：

1sysctl -w net.ipv4.ip_forward=0

如果系统启用了 IP 转发，一般也不影响基本实验，但 DR 模式的核心转发逻辑不是通过普通路由转发完成的。

清理已有 IPVS 规则

1ipvsadm -C

如果提示没有规则，可以忽略。

创建虚拟服务

使用轮询算法：

1ipvsadm -A -t 192.168.10.200:80 -s rr

参数说明：

  • -A：添加虚拟服务；
  • -t：TCP 服务；
  • 192.168.10.200:80：VIP 和端口；
  • -s rr：使用 Round Robin 轮询算法。

添加 Real Server

1ipvsadm -a -t 192.168.10.200:80 -r 192.168.10.11:80 -g -w 1
2ipvsadm -a -t 192.168.10.200:80 -r 192.168.10.12:80 -g -w 1

参数说明：

  • -a：添加 Real Server；
  • -r：指定 Real Server 地址；
  • -g：使用 DR 模式；
  • -w 1：权重为1。

静态调度算法

算法 代码 说明 适用场景
轮询 rr 依次分配给每个RS RS性能相近
加权轮询 wrr 按权重比例分配 RS性能不同
目标地址哈希 dh 根据目标IP哈希 特定目标固定RS
源地址哈希 sh 根据源IP哈希 会话保持

动态调度算法

算法 代码 说明 适用场景
最少连接 lc 选择连接数最少的RS 长连接服务
加权最少连接 wlc 结合权重和连接数 性能不同+长连接
最短期望延迟 sed (活动连接+1)/权重最小 均衡负载
永不排队 nq 无需等待的最少连接 短连接
基于局部性的最少连接 lblc 目标IP哈希+最少连接 缓存集群
带复制的lblc lblcr lblc+复制 高可用缓存

在使用keepalived之前，DR模式的实验面临的问题

  • LVS单节点，如果节点故障或LVS服务问题，业务受影响。（单节点问题）
  • RS节点异常，lvs 请求分发到异常节点，业务受影响。

解决办法

  • 单节点 -> 多节点（主主方式，主备方式）
  • 判断RS挂的方式：http 协议的请求，返回 200，OK

要能自动切换主从节点；

要能自动探测RS是否正常，异常时摘除相应节点，不再向异常节点转发。

 1#!/bin/bash
 2# scripts/realserver_dr.sh
 3# Support Multiple VIPs
 4
 5# VIP列表（用空格分隔）
 6VIPS="10.0.0.200 10.0.0.201 10.0.0.202"
 7
 8case "$1" in
 9    start)

11        
12        for VIP in ${VIPS}; do
13            echo "Configuring VIP: ${VIP}"
14            
15            # 配置IP
16            ip addr add ${VIP}/32 dev lo label lo:0 2>/dev/null
17            
18            # 添加路由
19            ip route add ${VIP}/32 dev lo scope host 2>/dev/null
20        done
21        
22        # 配置ARP（所有VIP共享）
23        echo "1" > /proc/sys/net/ipv4/conf/lo/arp_ignore
24        echo "2" > /proc/sys/net/ipv4/conf/lo/arp_announce
25        echo "1" > /proc/sys/net/ipv4/conf/all/arp_ignore
26        echo "2" > /proc/sys/net/ipv4/conf/all/arp_announce
27        
28        echo "RealServer Start OK"
29        ;;
30        
31    stop)
32        echo "Stopping RealServer DR configuration..."
33        
34        for VIP in ${VIPS}; do
35            echo "Removing VIP: ${VIP}"
36            
37            # 删除路由
38            ip route del ${VIP}/32 dev lo 2>/dev/null
39            
40            # 删除IP
41            ip addr del ${VIP}/32 dev lo 2>/dev/null
42        done
43        
44        echo "RealServer Stop OK"
45        ;;
46        
47    status)
48        echo "=== RealServer Status ==="
49        echo "Configured VIPs: ${VIPS}"
50        echo ""
51        
52        for VIP in ${VIPS}; do
53            if ip addr show lo | grep -q "${VIP}/32"; then
54                echo "✓ ${VIP} - ACTIVE"
55            else
56                echo "✗ ${VIP} - INACTIVE"
57            fi
58        done
59        
60        echo ""
61        echo "ARP Configuration:"
62        echo "  arp_ignore: $(cat /proc/sys/net/ipv4/conf/all/arp_ignore)"
63        echo "  arp_announce: $(cat /proc/sys/net/ipv4/conf/all/arp_announce)"
64        ;;
65        
66    *)
67        echo "Usage: $0 {start|stop|status}"
68        exit 1
69esac

14        
15        # 配置ARP（持久化）

17# LVS DR Mode ARP Configuration
18net.ipv4.conf.lo.arp_ignore = 1
19net.ipv4.conf.lo.arp_announce = 2
20net.ipv4.conf.all.arp_ignore = 1
21net.ipv4.conf.all.arp_announce = 2
22EOF
23        
24        # 应用配置
25        sysctl -p
26        
27        echo "RealServer Start OK (with persistent ARP config)"
28        ;;
29        
30    stop)
31        # 删除路由和IP
32        ip route del ${VIP}/32 dev lo 2>/dev/null
33        ip addr del ${VIP}/32 dev lo 2>/dev/null
34        
35        # 清理sysctl配置（可选）
36        sed -i '/# LVS DR Mode ARP Configuration/,+4d' /etc/sysctl.conf
37        
38        echo "RealServer Stop OK"
39        ;;
40        
41    *)
42        echo "Usage: $0 {start|stop}"
43        exit 1
44esac

2 测试keepalived主备切换

测试步骤：停主节点keepalived服务，查看备节点上的VIP地址，再次启动主节点keepalived服务，查看VIP地址有没有从备迁移到主。期望是不迁移。如果迁移了，请从以下步骤排查。

  • 检查备节点配置nopreempt：如果没有配置，vrrp_instance中增加nopreempt。
  • 检查主节点配置state：是不是配置的state MASTER，

nopreempt（非抢占模式）只在 state BACKUP 的节点上生效。当主节点是 MASTER 状态时，它恢复后会无视 nopreempt，直接抢回 VIP。

正确的非抢占配置

节点 state priority nopreempt 行为
主节点 BACKUP 100 配置 初次启动时优先级高会成为 MASTER
备节点 BACKUP 90 配置 成为 MASTER 后不会被抢占
