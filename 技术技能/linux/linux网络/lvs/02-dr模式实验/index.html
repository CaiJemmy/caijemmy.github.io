02 DR模式实验

DR 模式的关键是：

  • Director 和 Real Server 必须处于同一个二层广播域；
  • VIP 同时配置在 Director 和 Real Server 上；
  • Real Server 必须避免对 VIP 的 ARP 请求进行响应；
  • Director 只修改目标 MAC，不修改 IP 和端口；
  • Real Server 的响应绕过 Director，直接返回客户端。

1、安装软件

在 Director 上：

1apt update
2apt install -y ipvsadm nginx

在 Real Server 上：

1apt update
2apt install -y nginx

2、配置 Real Server

以下步骤需要在 RS1 和 RS2 上分别执行。

启动 Web 服务

1systemctl enable --now nginx

检查服务状态：

1systemctl status nginx
2ss -lntp | grep ':80'

设置不同的页面内容

Debian/Ubuntu 默认首页：/var/www/html/index.nginx-debian.html 或/var/www/html/index.html

在 RS1 上：

1# cat > /usr/share/nginx/html/index.html <<'EOF'
2cat > /var/www/html/index.nginx-debian.html <<'EOF'
3<h1>Response from RS1 - 192.168.10.11</h1>
4EOF

在 RS2 上：

1# cat > /usr/share/nginx/html/index.html <<'EOF'
2cat > /var/www/html/index.nginx-debian.html <<'EOF'
3<h1>Response from RS2 - 192.168.10.12</h1>
4EOF

先直接访问 Real Server，确认 Web 服务正常：

1curl http://192.168.10.11
2curl http://192.168.10.12

在 lo 接口配置 VIP

在 RS1、RS2 上分别执行：

1ip addr add 192.168.10.200/32 dev lo

检查：

1ip addr show dev lo

预期可以看到：

1inet 192.168.10.200/32 scope global lo

为什么配置到 lo 接口？

DR 模式中，Real Server 需要接收目标IP为 VIP 的数据包。因此，Real Server 必须认为 VIP 是本机地址。

将 VIP 配置在回环接口上，可以让 Real Server接收目标IP为 VIP 的报文，同时避免把 VIP作为正常接口地址直接暴露在二层网络中。

配置 ARP 抑制

这是 DR 模式最关键的配置之一。

在 RS1、RS2 上执行：

 1cat >> /etc/sysctl.d/99-lvs-dr.conf <<'EOF'
 2net.ipv4.conf.all.arp_ignore = 1
 3net.ipv4.conf.default.arp_ignore = 1
 4net.ipv4.conf.lo.arp_ignore = 1
 5
 6net.ipv4.conf.all.arp_announce = 2
 7net.ipv4.conf.default.arp_announce = 2
 8net.ipv4.conf.lo.arp_announce = 2
 9EOF
10
11sysctl --system

检查配置：

1sysctl net.ipv4.conf.all.arp_ignore
2sysctl net.ipv4.conf.all.arp_announce
3sysctl net.ipv4.conf.lo.arp_ignore
4sysctl net.ipv4.conf.lo.arp_announce

参数含义

arp_ignore = 1

只在目标IP配置于接收ARP请求的接口上时响应ARP。

这样，Real Server 不会通过物理网卡抢答 VIP 的ARP请求。

arp_announce = 2

发送ARP请求时，尽量使用最合适的接口地址作为源IP，减少多网卡环境下的ARP混乱。

3、配置 LVS Director

以下命令只在 Director 上执行。

加载 IPVS 模块

1modprobe ip_vs
2modprobe ip_vs_rr

检查：

1lsmod | grep ip_vs

给 Director 配置 VIP

1ip addr add 192.168.10.200/32 dev eth0

检查：

1ip addr show dev eth0

开启 IP 转发说明

LVS-DR 模式不依赖三层 IP 转发，通常不需要开启 net.ipv4.ip_forward。

可以保持：

1sysctl -w net.ipv4.ip_forward=0

如果系统启用了 IP 转发，一般也不影响基本实验，但 DR 模式的核心转发逻辑不是通过普通路由转发完成的。

清理已有 IPVS 规则

1ipvsadm -C

如果提示没有规则，可以忽略。

创建虚拟服务

使用轮询算法：

1ipvsadm -A -t 192.168.10.200:80 -s rr

参数说明：

  • -A：添加虚拟服务；
  • -t：TCP 服务；
  • 192.168.10.200:80：VIP 和端口；
  • -s rr：使用 Round Robin 轮询算法。

添加 Real Server

1ipvsadm -a -t 192.168.10.200:80 -r 192.168.10.11:80 -g -w 1
2ipvsadm -a -t 192.168.10.200:80 -r 192.168.10.12:80 -g -w 1

参数说明：

  • -a：添加 Real Server；
  • -r：指定 Real Server 地址；
  • -g：使用 DR 模式；
  • -w 1：权重为1。

查看配置

1ipvsadm -Ln

预期类似：

1IP Virtual Server version 1.2.1 (size=4096)
2Prot LocalAddress:Port Scheduler Flags
3  -> RemoteAddress:Port           Forward Weight ActiveConn InActConn
4TCP  192.168.10.200:80 rr
5  -> 192.168.10.11:80             Route   1      0          0
6  -> 192.168.10.12:80             Route   1      0          0

其中：

1Route

表示 DR 模式。

验证

Windows 10/11 PowerShell 自带真正的 curl：

1curl.exe --no-keepalive -s http://10.0.0.200:80

批量测试（PowerShell 脚本）

1for ($i=1; $i -le 10; $i++) {
2    Write-Host "请求 ${i}: " -NoNewline
3    $response = Invoke-WebRequest -Uri http://10.0.0.200:80 -DisableKeepAlive -UseBasicParsing
4    $response.Content
5    Start-Sleep -Milliseconds 500
6}
警告

不能在 ds 和 rs 主机上做 curl 测试，因为这些主机上有 vip ，tcp 无法建立连接。
