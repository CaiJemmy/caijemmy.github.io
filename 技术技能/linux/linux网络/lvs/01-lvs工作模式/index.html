01 LVS工作模式

LVS（Linux Virtual Server）是Linux内核级别的负载均衡解决方案，有三种主要工作模式：

1. NAT模式（Network Address Translation）

工作原理：

  • Director Server（调度器）接收客户端请求
  • 修改请求包的目标IP为Real Server IP
  • Real Server处理后，响应包发回Director
  • Director修改源IP为VIP，返回给客户端

特点：

  • Real Server可使用任何操作系统
  • Real Server只需配置Director为网关
  • 节省公网IP（只需Director有公网IP）
  • Director成为性能瓶颈（请求和响应都经过）
  • 支持端口映射

适用场景：
小规模集群（10-20台），Real Server在私网

2. DR模式（Direct Routing，直接路由）

工作原理：

  • Director接收请求，修改MAC地址为Real Server MAC
  • Real Server处理后，直接返回给客户端（不经过Director）
  • Real Server配置VIP在lo接口（抑制ARP）

特点：

  • 性能最高（响应不经过Director）
  • Director不是瓶颈
  • 支持大规模集群
  • Real Server必须与Director在同一网段
  • 不支持端口映射
  • Real Server需要抑制ARP响应

适用场景：
大规模高性能集群，最常用模式

关键配置：

1# Real Server需要配置（抑制ARP）
2echo 1 > /proc/sys/net/ipv4/conf/lo/arp_ignore
3echo 2 > /proc/sys/net/ipv4/conf/lo/arp_announce
4echo 1 > /proc/sys/net/ipv4/conf/all/arp_ignore
5echo 2 > /proc/sys/net/ipv4/conf/all/arp_announce
6
7# lo接口配置VIP
8ifconfig lo:0 VIP netmask 255.255.255.255

3. TUN模式（IP Tunneling，IP隧道）

工作原理：

  • Director将请求包封装在新的IP包中（IP隧道）
  • Real Server解封装后处理请求
  • Real Server直接返回响应给客户端

特点：

  • Real Server可跨地域部署（不受网段限制）
  • 响应不经过Director
  • 适合跨机房负载均衡
  • Real Server需要支持IP隧道
  • 不支持端口映射
  • 配置复杂

适用场景：
跨地域、跨机房的大规模集群

四种调度算法

LVS支持10种调度算法，常用的有：

静态算法：

  • RR（Round Robin）：轮询，平均分配
  • WRR（Weighted RR）：加权轮询，按权重分配
  • DH（Destination Hashing）：目标地址哈希
  • SH（Source Hashing）：源地址哈希

动态算法：

  • LC（Least Connections）：最少连接，分配给连接数最少的服务器
  • WLC（Weighted LC）：加权最少连接（默认算法）
  • SED（Shortest Expected Delay）：最短期望延迟
  • NQ（Never Queue）：永不排队
  • LBLC：基于本地的最少连接
  • LBLCR：基于本地的带复制功能的最少连接

三种模式对比

特性 NAT模式 DR模式 TUN模式
性能 较低 最高 高
网络要求 私网 同网段 可跨网段
端口映射 支持 不支持 不支持
Real Server配置 简单 中等（需抑制ARP） 复杂（需支持隧道）
Director负载 高（双向流量） 低（仅入站） 低（仅入站）
Real Server OS 任意 任意 需支持IP隧道
公网IP需求 仅Director 仅Director 仅Director
适用场景 小规模 大规模高性能 跨地域部署
