nslookup 命令

nslookup (Name Server Lookup) 是用于查询 DNS 域名解析的工具，可以查看域名对应的 IP 地址、验证 DNS 配置、排查网络问题。

基本语法

1nslookup [选项] [域名或IP] [DNS服务器]

基本用法

查询域名的 IP 地址

1nslookup www.google.com

输出示例：

1Server:         192.168.1.1           # 使用的 DNS 服务器
2Address:        192.168.1.1#53        # DNS 服务器地址和端口
3
4Non-authoritative answer:             # 非权威应答（来自缓存）
5Name:   www.google.com
6Address: 142.250.185.36               # IPv4 地址
7Name:   www.google.com
8Address: 2607:f8b0:4004:c07::68       # IPv6 地址

反向查询（IP 查域名）

1nslookup 8.8.8.8

输出：

1Server:         192.168.1.1
2Address:        192.168.1.1#53
3
4Non-authoritative answer:
58.8.8.8.in-addr.arpa    name = dns.google.     # PTR 记录

指定 DNS 服务器查询

1# 使用 Google DNS 查询
2nslookup www.baidu.com 8.8.8.8
3
4# 使用 Cloudflare DNS 查询
5nslookup www.baidu.com 1.1.1.1
6
7# 使用阿里 DNS 查询
8nslookup www.baidu.com 223.5.5.5

输出：

 1Server:         8.8.8.8
 2Address:        8.8.8.8#53            # 明确显示使用的 DNS 服务器
 3
 4Non-authoritative answer:
 5www.baidu.com   canonical name = www.a.shifen.com.
 6www.a.shifen.com        canonical name = www.wshifen.com.
 7Name:   www.wshifen.com
 8Address: 103.235.47.188
 9Name:   www.wshifen.com
10Address: 103.235.46.96

Kubernetes 中的 nslookup

测试 Service DNS 解析

1bash# 启动临时 Pod
2kubectl run -it --rm debug --image=busybox:1.35 --restart=Never -- sh
3
4# 在 Pod 内执行
5nslookup kubernetes
6nslookup kubernetes.default
7nslookup kubernetes.default.svc.cluster.local

输出示例：

1Server:    10.96.0.10                          # CoreDNS 地址
2Address 1: 10.96.0.10 kube-dns.kube-system.svc.cluster.local
3
4Name:      kubernetes.default.svc.cluster.local
5Address 1: 10.96.0.1 kubernetes.default.svc.cluster.local

测试不同类型的 Service

 1bash# ========== ClusterIP Service ==========
 2nslookup backend-api.default.svc.cluster.local
 3# 输出: ClusterIP 地址
 4
 5# ========== Headless Service ==========
 6nslookup mysql-headless.default.svc.cluster.local
 7# 输出: 所有 Pod 的 IP 地址（A 记录）
 8# Address 1: 10.1.1.5 mysql-0.mysql-headless.default.svc.cluster.local
 9# Address 2: 10.1.1.6 mysql-1.mysql-headless.default.svc.cluster.local
10# Address 3: 10.1.1.7 mysql-2.mysql-headless.default.svc.cluster.local
11
12# ========== ExternalName Service ==========
13nslookup redis-cache.default.svc.cluster.local
14# 输出: CNAME 记录，指向外部域名
15# redis-cache.default.svc.cluster.local canonical name = redis.external.com
16
17# ========== StatefulSet Pod DNS ==========
18nslookup mysql-0.mysql-headless.default.svc.cluster.local
19# 输出: 特定 Pod 的 IP

测试跨命名空间访问

 1bash# 完整域名格式：<service>.<namespace>.svc.cluster.local
 2
 3# 访问 default 命名空间的服务
 4nslookup backend-api.default.svc.cluster.local
 5
 6# 访问 production 命名空间的服务
 7nslookup web-api.production.svc.cluster.local
 8
 9# 访问 kube-system 命名空间的服务
10nslookup kube-dns.kube-system.svc.cluster.local

DNS 搜索域

1bash# 在 Pod 内查看 /etc/resolv.conf
2cat /etc/resolv.conf

输出：

1nameserver 10.96.0.10                          # CoreDNS IP
2search default.svc.cluster.local svc.cluster.local cluster.local
3options ndots:5

解读：

  • search：DNS 搜索域列表
  • 查询 backend-api 时，会依次尝试：
    1. backend-api.default.svc.cluster.local
    2. backend-api.svc.cluster.local
    3. backend-api.cluster.local
    4. backend-api（失败）
  • ndots:5：域名中点数 ≥5 时，直接查询；否则按搜索域查询
