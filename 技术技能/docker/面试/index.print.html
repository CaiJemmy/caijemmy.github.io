01 Dockerfile 面试

一、基础概念题

1. FROM、RUN、CMD、ENTRYPOINT 的区别？

FROM

  • 指定基础镜像
  • 必须是 Dockerfile 的第一条指令（除了 ARG）
1FROM ubuntu:22.04
2FROM scratch  # 空白镜像

RUN

  • 构建时执行命令，结果会被提交到镜像层
  • 每个 RUN 创建一层新的镜像层
1RUN apt-get update && apt-get install -y nginx
2RUN npm install

CMD

  • 容器启动时的默认命令
  • 可以被 docker run 的参数覆盖
  • 一个 Dockerfile 只能有一个 CMD（多个只有最后一个生效）
1CMD ["nginx", "-g", "daemon off;"]
2CMD npm start

ENTRYPOINT

  • 容器启动时的入口点
  • 不会被 docker run 参数覆盖，但可以通过 --entrypoint 覆盖
  • CMD 的内容会作为 ENTRYPOINT 的参数
1ENTRYPOINT ["python"]
2CMD ["app.py"]
3# 等同于执行：python app.py

对比：

 1# 示例 1：只有 CMD
 2CMD ["echo", "hello"]
 3# docker run myimage          → 输出 hello
 4# docker run myimage echo bye → 输出 bye（CMD 被覆盖）
 5
 6# 示例 2：ENTRYPOINT + CMD
 7ENTRYPOINT ["echo"]
 8CMD ["hello"]
 9# docker run myimage          → 输出 hello
10# docker run myimage bye      → 输出 bye（CMD 被替换）

2. COPY 和 ADD 的区别？

特性 COPY ADD
复制文件 支持 支持
复制目录 支持 支持
自动解压 tar 不支持 支持
支持 URL 不支持 支持
推荐使用 官方推荐 特殊场景 
1# COPY：简单明确（推荐）
2COPY app.py /app/
3COPY requirements.txt /app/
4
5# ADD：额外功能
6ADD app.tar.gz /app/      # 自动解压
7ADD http://example.com/file.txt /app/  # 支持 URL（不推荐，用 RUN wget）

最佳实践：优先使用 COPY，除非需要自动解压 tar。

3. ARG 和 ENV 的区别？

ARG

  • 构建时变量
  • 只在构建过程中有效
  • 不会存在于最终镜像中

ENV

  • 环境变量
  • 构建和运行时都有效
  • 会存在于最终镜像中
 1# ARG：构建时参数
 2ARG NODE_VERSION=18
 3FROM node:${NODE_VERSION}
 4
 5ARG BUILD_ENV=production
 6RUN echo "Building for ${BUILD_ENV}"
 7
 8# ENV：运行时环境变量
 9ENV APP_ENV=production
10ENV PORT=3000
11
12# ARG 可以设置 ENV 的默认值
13ARG DEFAULT_PORT=8080
14ENV PORT=${DEFAULT_PORT}

构建和运行：

1# 构建时传递 ARG
2docker build --build-arg NODE_VERSION=20 .
3
4# 运行时覆盖 ENV
5docker run -e PORT=9000 myimage

4. CMD 的三种格式？

 1# 1. exec 格式（推荐，JSON 数组）
 2CMD ["executable", "param1", "param2"]
 3CMD ["nginx", "-g", "daemon off;"]
 4
 5# 2. shell 格式
 6CMD executable param1 param2
 7CMD nginx -g daemon off;
 8
 9# 3. 作为 ENTRYPOINT 的参数
10ENTRYPOINT ["python"]
11CMD ["app.py"]

区别：

1# exec 格式：不会启动 shell，PID 1 是应用本身
2CMD ["nginx", "-g", "daemon off;"]
3# 容器内：PID 1 = nginx
4
5# shell 格式：会启动 /bin/sh -c，PID 1 是 shell
6CMD nginx -g daemon off;
7# 容器内：PID 1 = /bin/sh -c "nginx -g daemon off;"
8#         PID 2 = nginx

为什么 exec 格式更好？

  • PID 1 是应用本身，能正确处理信号（SIGTERM）
  • 容器停止时能优雅退出
  • 避免僵尸进程

二、优化题

5. 如何优化镜像大小？

技巧 1：使用多阶段构建

 1# 构建阶段
 2FROM node:18 AS builder
 3WORKDIR /app
 4COPY package*.json ./
 5RUN npm ci --only=production
 6COPY . .
 7RUN npm run build
 8
 9# 运行阶段
10FROM node:18-alpine
11WORKDIR /app
12COPY --from=builder /app/dist ./dist
13COPY --from=builder /app/node_modules ./node_modules
14CMD ["node", "dist/index.js"]
15
16# 镜像大小：从 1.2GB → 150MB

技巧 2：合并 RUN 指令

 1# 不好：每个 RUN 创建一层
 2RUN apt-get update
 3RUN apt-get install -y nginx
 4RUN apt-get clean
 5# 三层，中间层仍然占用空间
 6
 7# 好：一个 RUN，一层
 8RUN apt-get update \
 9    && apt-get install -y nginx \
10    && apt-get clean \
11    && rm -rf /var/lib/apt/lists/*
12# 一层，最小化体积

技巧 3：使用 .dockerignore

1# .dockerignore
2node_modules
3.git
4.env
5*.log
6test/
7docs/

技巧 4：选择精简基础镜像

 1# 大：1.2GB
 2FROM ubuntu:22.04
 3
 4# 中：200MB
 5FROM node:18-slim
 6
 7# 小：50MB
 8FROM node:18-alpine
 9
10# 最小：从头构建
11FROM scratch

6. 如何优化构建缓存？

原则：把变化少的指令放前面，变化多的放后面

 1# 不好：代码变化会导致依赖重装
 2FROM node:18
 3WORKDIR /app
 4COPY . .                    # 代码频繁变化
 5RUN npm install             # 每次都重装
 6
 7# 好：利用缓存分层
 8FROM node:18
 9WORKDIR /app
10COPY package*.json ./       # 依赖文件单独复制
11RUN npm install             # 只有依赖变化时才重装
12COPY . .                    # 代码变化不影响上层
13RUN npm run build

实际例子：

 1# Python 项目
 2FROM python:3.11-slim
 3WORKDIR /app
 4
 5# 1. 先复制依赖文件（变化少）
 6COPY requirements.txt .
 7RUN pip install --no-cache-dir -r requirements.txt
 8
 9# 2. 再复制代码（变化多）
10COPY . .
11
12CMD ["python", "app.py"]

7. 多阶段构建的完整示例？

 1# ============================================
 2# 阶段 1：构建依赖
 3# ============================================
 4FROM node:18 AS dependencies
 5WORKDIR /app
 6COPY package*.json ./
 7RUN npm ci --only=production
 8
 9# ============================================
10# 阶段 2：构建应用
11# ============================================
12FROM node:18 AS builder
13WORKDIR /app
14COPY package*.json ./
15RUN npm ci
16COPY . .
17RUN npm run build
18RUN npm run test
19
20# ============================================
21# 阶段 3：运行时镜像
22# ============================================
23FROM node:18-alpine
24WORKDIR /app
25
26# 只复制必需的文件
27COPY --from=dependencies /app/node_modules ./node_modules
28COPY --from=builder /app/dist ./dist
29COPY package.json ./
30
31# 安全：非 root 用户运行
32RUN addgroup -g 1001 -S nodejs \
33    && adduser -S nodejs -u 1001
34USER nodejs
35
36EXPOSE 3000
37CMD ["node", "dist/index.js"]

好处：

  • 构建工具不在最终镜像中
  • 测试失败不会生成镜像
  • 最终镜像只包含运行时依赖

8. 如何处理敏感信息（密钥、密码）？

** 错误做法：**

1# 方法 1：硬编码（最危险）
2ENV DB_PASSWORD=secret123
3
4# 方法 2：通过 ARG（会保留在镜像历史中）
5ARG API_KEY
6RUN echo $API_KEY > /app/config

正确做法：

方法 1：运行时注入

1docker run -e DB_PASSWORD=secret123 myimage
2docker run --env-file .env myimage

方法 2：Docker Secrets（Swarm/Compose）

 1# docker-compose.yml
 2version: '3.8'
 3services:
 4  app:
 5    image: myapp
 6    secrets:
 7      - db_password
 8
 9secrets:
10  db_password:
11    file: ./db_password.txt

方法 3：Kubernetes Secrets

 1apiVersion: v1
 2kind: Pod
 3spec:
 4  containers:
 5  - name: app
 6    env:
 7    - name: DB_PASSWORD
 8      valueFrom:
 9        secretKeyRef:
10          name: db-secret
11          key: password

方法 4：构建时挂载（BuildKit）

1# 使用 secret mount（不会保留在镜像中）
2RUN --mount=type=secret,id=github_token \
3    git clone https://$(cat /run/secrets/github_token)@github.com/private/repo.git
1docker build --secret id=github_token,src=./token.txt .

四、高级题

11. 什么是 BuildKit？有什么优势？

BuildKit 是 Docker 新一代构建引擎。

启用方式：

 1# 方法 1：环境变量
 2export DOCKER_BUILDKIT=1
 3docker build .
 4
 5# 方法 2：配置文件
 6# /etc/docker/daemon.json
 7{
 8  "features": {
 9    "buildkit": true
10  }
11}

优势：

1. 并行构建

 1FROM alpine AS build1
 2RUN sleep 5 && echo "build1"
 3
 4FROM alpine AS build2
 5RUN sleep 5 && echo "build2"
 6
 7FROM alpine
 8COPY --from=build1 /etc/os-release /build1
 9COPY --from=build2 /etc/os-release /build2
10# build1 和 build2 并行执行，总耗时 5 秒而非 10 秒

2. 缓存挂载

1# 持久化包管理器缓存
2RUN --mount=type=cache,target=/var/cache/apt \
3    apt-get update && apt-get install -y nginx
4
5# npm 缓存
6RUN --mount=type=cache,target=/root/.npm \
7    npm install

3. 绑定挂载

1# 临时挂载文件（不复制到镜像）
2RUN --mount=type=bind,source=package.json,target=/tmp/package.json \
3    cat /tmp/package.json

4. SSH 挂载

1# 使用宿主机 SSH 密钥（不保存在镜像中）
2RUN --mount=type=ssh \
3    git clone git@github.com:private/repo.git
1docker build --ssh default .

14. 如何构建跨平台镜像？

使用 buildx（支持 AMD64、ARM64 等）

 1# 创建 builder
 2docker buildx create --name multiarch --use
 3
 4# 构建并推送多架构镜像
 5docker buildx build \
 6    --platform linux/amd64,linux/arm64,linux/arm/v7 \
 7    -t myregistry/myimage:latest \
 8    --push .
 9
10# 查看支持的平台
11docker buildx imagetools inspect myregistry/myimage:latest

Dockerfile 示例：

 1FROM --platform=$BUILDPLATFORM golang:1.21 AS builder
 2ARG TARGETPLATFORM
 3ARG BUILDPLATFORM
 4RUN echo "Building on $BUILDPLATFORM for $TARGETPLATFORM"
 5
 6WORKDIR /app
 7COPY . .
 8RUN CGO_ENABLED=0 GOOS=${TARGETOS} GOARCH=${TARGETARCH} \
 9    go build -o app
10
11FROM alpine:latest
12COPY --from=builder /app/app /usr/local/bin/
13CMD ["app"]

六、陷阱题

18. 以下 Dockerfile 有什么问题？

1FROM ubuntu:22.04
2WORKDIR /app
3COPY . .
4RUN apt-get install -y python3
5RUN pip install -r requirements.txt
6CMD python3 app.py

问题：

  1. 没有 apt-get update

    1# 错误
2RUN apt-get install -y python3
3
4# 正确
5RUN apt-get update && apt-get install -y python3

  2. 没有清理缓存

    1# 正确
2RUN apt-get update \
3    && apt-get install -y python3 \
4    && rm -rf /var/lib/apt/lists/*

  3. RUN 指令太多，每个创建一层

    1# 正确：合并
2RUN apt-get update \
3    && apt-get install -y python3 python3-pip \
4    && rm -rf /var/lib/apt/lists/* \
5    && pip install -r requirements.txt

  4. CMD 使用 shell 格式

    1# 错误
2CMD python3 app.py
3
4# 正确
5CMD ["python3", "app.py"]

  5. 没有指定 pip 版本

    1# 正确
2RUN pip install --no-cache-dir -r requirements.txt

  6. 使用 root 用户

    1# 正确
2RUN useradd -m appuser
3USER appuser

19. 这两个 Dockerfile 有什么区别？

1# Dockerfile A
2RUN apt-get update
3RUN apt-get install -y nginx
4RUN apt-get clean
5
6# Dockerfile B
7RUN apt-get update \
8    && apt-get install -y nginx \
9    && apt-get clean

答案：

Dockerfile A：

  • 创建 3 层镜像
  • 第一层包含 apt 缓存（约 100MB）
  • 第三层删除缓存，但第一层仍然占用空间
  • 最终镜像更大

Dockerfile B：

  • 创建 1 层镜像
  • 在同一层中安装和清理，缓存不保留
  • 最终镜像更小

验证：

 1# 构建 A
 2docker build -t test-a -f Dockerfile.a .
 3docker history test-a
 4
 5# 构建 B
 6docker build -t test-b -f Dockerfile.b .
 7docker history test-b
 8
 9# 对比大小
10docker images | grep test-

14    APP_VERSION=${APP_VERSION}
15
16# 4. 安装依赖（一个 RUN，清理缓存）
17RUN apk add --no-cache \
18        curl \
19        tini \
20    && rm -rf /var/cache/apk/*
21
22# 5. 创建非 root 用户
23RUN addgroup -g 1001 -S appgroup \
24    && adduser -S appuser -u 1001 -G appgroup

26# 6. 设置工作目录
27WORKDIR /app
28
29# 7. 复制依赖文件（利用缓存）
30COPY --chown=appuser:appgroup package*.json ./
31
32# 8. 安装应用依赖
33RUN npm ci --only=production \
34    && npm cache clean --force
35
36# 9. 复制应用代码
37COPY --chown=appuser:appgroup . .
38
39# 10. 切换到非 root 用户
40USER appuser
41
42# 11. 暴露端口
43EXPOSE 3000
44
45# 12. 添加健康检查
46HEALTHCHECK --interval=30s --timeout=3s --start-period=5s --retries=3 \
47    CMD curl -f http://localhost:3000/health || exit 1

51      version="${APP_VERSION}" \
